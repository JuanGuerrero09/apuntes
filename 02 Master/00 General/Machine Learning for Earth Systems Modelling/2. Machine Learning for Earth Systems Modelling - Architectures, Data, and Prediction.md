# Module 2: Neural Architectures for Atmospheric Dynamics (Part 1)

## Neural Networks

### Fundamental concepts

- **Definition:** A Neural Network (NN) is a parameterized mathematical function $f_\theta: \mathcal{X} \to \mathcal{Y}$ that maps an input space $\mathcal{X}$ (e.g., text, audio, images, or atmospheric states) to an output space $\mathcal{Y}$.
- **Universal Approximation Theorem:** A feedforward network with a single hidden layer containing a sufficient number of non-linear neurons can approximate any continuous function on compact subsets of $\mathbb{R}^n$ to arbitrary precision.
- **Atmospheric Context:** NNs are used to approximate complex, non-linear atmospheric fluid dynamics and sub-grid physics (e.g., radiative transfer, cloud microphysics, convection parameterization) where analytical solutions are computationally intractable.
### Neuron, layer, and MLP

- **Neuron:** The fundamental computational unit. It takes an input vector $\mathbf{x} \in \mathbb{R}^d$, computes an affine transformation using a weight vector $\mathbf{w}$ and scalar bias $b$, and applies a non-linear activation function $\sigma$:    $$y = \sigma(\mathbf{w}^T \mathbf{x} + b) = \sigma\left(\sum_{i=1}^{d} w_i x_i + b\right)$$
- **Layer:** A collection of multiple parallel neurons operating at the same depth in the network hierarchy.

- **Multi-Layer Perceptron (MLP):** A stack of sequentially connected layers where information flows strictly forward (feedforward):    
$$\mathbf{h}^{(1)} = \sigma_1(\mathbf{W}^{(1)}\mathbf{x} + \mathbf{b}^{(1)})$$    $$\mathbf{h}^{(2)} = \sigma_2(\mathbf{W}^{(2)}\mathbf{h}^{(1)} + \mathbf{b}^{(2)})$$
$$\hat{\mathbf{y}} = \mathbf{W}^{(L)}\mathbf{h}^{(L-1)} + \mathbf{b}^{(L)}$$
 
- **Depth ($L$):** The total number of parameterized layers in the model. Deep networks learn hierarchical abstractions.

- **Width ($W_{max}$):** The maximum number of neurons in any single layer.

- **Linear Stacking Limitation:** Stacking purely linear layers without non-linear activations yields a composite function $\hat{\mathbf{y}} = \mathbf{W}_3 \mathbf{W}_2 \mathbf{W}_1 \mathbf{x} + \mathbf{b}$, which collapses algebraically into a single matrix multiplication $\mathbf{W}_{\text{eff}}\mathbf{x} + \mathbf{b}_{\text{eff}}$. Non-linearities are required to represent non-linear system dynamics.

### Allowing nonlinearity & Activation Functions

Applying non-linear activation functions introduces expressive capacity, stabilizes optimization, and enables physical constraints:

- **ReLU (Rectified Linear Unit):** $\text{ReLU}(z) = \max(0, z)$.    
    - _Pros:_ Computationally efficient, prevents vanishing gradients for positive inputs.
    - _Cons:_ "Dying ReLU" problem where neurons get permanently deactivated if gradients become zero.

- **LeakyReLU / GELU (Gaussian Error Linear Unit):**    
    - $\text{LeakyReLU}(z) = \max(\alpha z, z)$ where $\alpha \approx 0.01$.
    - $\text{GELU}(z) = z \Phi(z)$ (where $\Phi(z)$ is the standard Gaussian cumulative distribution function). GELU is widely used in state-of-the-art weather transformers (e.g., FourCastNet, ClimaX).

- **Sigmoid Activation:** $\sigma(z) = \frac{1}{1 + e^{-z}}$.    
    - Scales outputs to the range $(0, 1)$. Useful for probabilistic outputs or relative humidity fraction. Saturates at extreme values, causing vanishing gradients.

- **Softplus / Exponential (Physical Constraints):** $f(z) = \ln(1 + e^z)$. Enforces strict positivity for variables that cannot be negative (e.g., precipitation rate, cloud liquid water, surface solar radiation).


### How do we optimize the parameters?

- **Loss Function $L(\theta)$:** Measures the discrepancy between model predictions $\hat{\mathbf{y}} = f_\theta(\mathbf{x})$ and target truths $\mathbf{y}$.
- **Gradient Descent:** Iterative optimization algorithm that updates parameters $\theta$ in the direction of steepest loss descent:
$$\theta^{(t+1)} = \theta^{(t)} - \eta \nabla_\theta L(\theta^{(t)})$$  _(where $\eta$ is the learning rate)._

- **Backpropagation:** Efficient evaluation of the gradient $\nabla_\theta L$ using the multi-variable **Chain Rule** of calculus, propagating error signals backward from the output layer to early layers.

- **Differentiability Requirement:** All operations and layers within the neural network must be almost everywhere differentiable to allow continuous gradient computation.

### Pillars for scaling the model

1. **Compute:** Hardware accelerators (GPUs, TPUs) capable of massively parallel floating-point operations (FLOPS).
2. **Data:** High-resolution atmospheric datasets (e.g., ERA5 reanalysis with $>50$ years of hourly global data across 137 pressure levels).
3. **Model:** Architectures scaled in depth, width, and parameter capacity to absorb large data volumes without underfitting.

### Regularization

Techniques designed to prevent overfitting (where the network memorizes noise or specific training years rather than general physical laws):

- **Normalization:**
    - **Batch Normalization (BatchNorm):** Normalizes activations across the mini-batch dimension. Can be unstable in atmospheric modeling if batch sizes are small or if spatial correlations violate IID assumptions.
    - **Layer Normalization (LayerNorm):** Normalizes across feature/channel dimensions independently for each sample. Highly stable and standard in transformer/weather architectures.
    - **Group Normalization (GroupNorm):** Divides channels into groups and normalizes within each group; independent of batch size.

- **Dropout:** Randomly sets a fraction $p$ of neuron activations to zero during each training forward pass.
    - _Correction on Random Forests comparison:_ Unlike Random Forests (which build an ensemble of independent decision trees via bagging), Dropout forces individual neurons within a single network to learn robust features without co-adapting on neighboring neurons.

- **Residual Connections (Skip Connections):** Computes $y = f(x) + x$.
    - Prevents vanishing gradients in deep networks by providing a direct linear highway for gradient propagation during backpropagation.
    - Smooths the optimization loss landscape.

### Earth System Modelling (Domain-Specific Nuances)

#### Data Processing

- **Per-Variable Normalization:** Atmospheric variables vary across orders of magnitude (e.g., Specific Humidity $q \approx 10^{-3} \text{ kg/kg}$, Geopotential $Z \approx 10^5 \text{ m}^2/\text{s}^2$). Variables must be scaled individually to zero mean and unit variance ($z$-score normalization) or bounded $[0, 1]$:
$$\tilde{x}_{v, p} = \frac{x_{v, p} - \mu_{v, p}}{\sigma_{v, p}}$$
 
_(where $v$ is the variable and $p$ is the pressure level)._

- **Training Statistics Leakage Prevention:** $\mu$ and $\sigma$ must be computed strictly on the training temporal split (e.g., 1979–2015) and applied identically to validation (2016–2017) and testing sets (2018+).


#### Modelling Strategies

- **Exploiting Spatiotemporal Dynamics:** Atmospheric phenomena follow physical conservation laws (mass, momentum, energy) across space $(x, y, z)$ and time $t$.

- **Learning Increments/Residuals (Tendency Modeling):** Instead of directly predicting the full future state $\mathbf{x}_{t+\Delta t}$, models predict the change/increment $\Delta \mathbf{x}$:
$$\mathbf{x}_{t+\Delta t} = \mathbf{x}_t + \mathcal{N}_\theta(\mathbf{x}_t, \Delta t)$$
    - _Physical Link:_ This mimics forward numerical integration (Euler scheme) for atmospheric differential equations $\frac{\partial \mathbf{x}}{\partial t} = \mathcal{F}(\mathbf{x})$.

- **Memory Constraints:** High-resolution atmospheric grids (e.g., $0.25^\circ \approx 721 \times 1440$ horizontal grid points across 37 pressure levels and tens of variables) exceed GPU VRAM quickly during autoregressive rollout steps.


#### Validation & Evaluation

- **Normalized Space Loss:** Gradients and optimization loss are computed in standardized/scaled space so high-magnitude variables do not dominate parameter updates.

- **Physical Unit Metrics:** Final reporting must un-scale predictions back to physical units (e.g., Kelvin, m/s, hPa) to judge real-world skill.

- **Area/Latitude Weighting:** On standard equirectangular (latitude-longitude) grids, grid cells shrink toward the poles. Loss functions and metrics must include latitude weighting $w(i) = \cos(\phi_i)$ to ensure equal spatial coverage representation:    $$\text{LWRMSE} = \sqrt{\frac{1}{N_{\text{lat}} N_{\text{lon}}} \sum_{i=1}^{N_{\text{lat}}} \sum_{j=1}^{N_{\text{lon}}} w(i) \left(\hat{y}_{i,j} - y_{i,j}\right)^2}$$
    
- **Distribution Shifts:**
    - **Seasonal & Diurnal Cycles:** Models must generalize across changing solar insolation angles throughout the year and day/night transitions.
    - **Out-of-Distribution (OOD) Climate Drift:** Models trained on historical data must handle warming trends and unprecedented extreme weather events driven by climate change.

### Terminology

#### Neural network terminology

- **Neuron:** The basic unit of a neural network, which takes a weighted sum of its inputs, adds a constant (called bias), and passes the result through a (non-linear) activation function.
- **Weight Matrix:** A matrix of learnable parameters $\mathbf{W}$ defining connection strengths between layers, optimized during backpropagation.
- **Activation Function:** A non-linear mapping applied element-wise to layer outputs enabling networks to approximate non-linear dynamic functions.
- **Dense (Fully-Connected) Layer:** A layer where every neuron receives inputs from all neurons of the preceding layer.
- **Multi-Layer Perceptron (MLP):** A feedforward neural network comprising stacked dense layers separated by non-linear activations.

#### Neural network training

- **Forward Pass:** The evaluation steps passing input data forward through network operations to generate predictions.
- **Loss Function:** A scalar-valued function $L(\hat{y}, y)$ quantifying model error against ground truth targets.
- **Backward Pass (Backpropagation):** The continuous evaluation of partial derivatives $\frac{\partial L}{\partial w_i}$ for all weights via the chain rule.
- **Gradient Descent:** Optimization algorithm updating model weights proportional to the negative gradient of the loss function.
- **Batch (Mini-batch):** A subset of training samples processed concurrently to estimate true loss gradients during stochastic optimization.
- **Learning Rate ($\eta$):** Hyperparameter governing the step-size taken along the negative gradient vector per update step.
- **Epoch:** One complete pass through the entire training dataset.
- **Auto-Differentiation:** Software execution framework (e.g., PyTorch, JAX) that builds dynamic computational graphs to compute exact gradients automatically.

#### Techniques to improve training

- **Input/Output Normalization:** Standardizing data to zero mean and unit variance ($\mu=0, \sigma=1$) or scaling to $[0,1]$ to prevent large-magnitude features from dominating gradient updates.
- **Layer Normalization:** Normalizing feature activations across channels for a single sample; highly effective for Transformers and dynamic spatial models.
- **Batch Normalization:** Normalizing feature activations across the mini-batch dimension per feature channel.
- **Dropout:** Randomly setting a fraction $p$ of neuron activations to zero during training to enforce redundant, decorrelated representations and minimize overfitting.
- **Residual/Skip Connections:** Architectural pathways that add a layer's input directly to its output ($\mathbf{x} + f(\mathbf{x})$), preserving gradient flow in deep networks.

## Convolutional neural networks

### Motivation for convolutions

- **MLP Parameter Explosion:** For a $1000 \times 1000$ single-channel atmospheric map, an MLP with 100 hidden neurons requires $(10^6 \times 100) = 10^8$ weights for layer 1 alone.
- **Constraining the Hypothesis Space:** CNNs enforce spatial structural assumptions directly into the architecture, preventing parameter overfitting and drastically improving spatial generalization.

### What structure do images have?

- **Spatial locality:** Neighboring pixels tend to form meaningful local structures (e.g., edges, textures) and are more strongly correlated than distant pixels. E.g., Adjacent grid points in a climate model share similar temperature, pressure, or moisture values, with local spatial gradients dictating atmospheric dynamics.

- **Compositional structure:** Simple low-level features (edges, contours) combine hierarchically to form mid-level motifs and complex high-level objects. E.g., Local temperature and moisture gradients combine to form frontal boundaries, which in turn assemble into synoptic-scale mid-latitude cyclones or atmospheric rivers.

- **Translation invariance:** The model's final output or prediction remains identical even if the input feature shifts to a different location in space ($f(T_\Delta(x)) = f(x)$). E.g., A model identifying whether an extreme event is present on a global map returns "cyclone detected" regardless of whether the cyclone is positioned over the Atlantic or the Pacific Ocean.

- **Translation equivariance:** Shifting the input spatially produces an identically shifted feature representation in the output ($f(T_\Delta(x)) = T_\Delta(f(x))$). E.g., If a low-pressure system shifts 5 degrees eastward across a meteorological grid, the internal convolutional feature map detecting low pressure shifts eastward by the exact same 5 degrees.

### Why Convolutional Neural Networks for Images?

In previous sessions, you utilized fully connected neural networks, also known as Multi-Layer Perceptrons (MLPs). While powerful, MLPs face two significant limitations when processing image and spatial grid data.

#### Parameter Explosion

Images represent high-dimensional data. For a standard $28 \times 28$ grayscale image ($784$ features), a single hidden layer with 100 neurons requires $784 \times 100 = 78,400$ weights. For modern high-definition images or global ERA5 reanalysis ($721 \times 1440$ grid points across 37 pressure levels), parameter counts become computationally prohibitive and lead to rapid overfitting.

#### Lack of Spatial Awareness

Flattening a 2D or 3D grid into a 1D vector completely destroys spatial topology (left-right, top-bottom relationships). If a visual pattern shifts by just a few pixels, the resulting vector changes drastically, requiring the model to learn the same feature (like an atmospheric front) separately for every possible coordinate in the grid.

### The CNN Solution

CNNs utilize two fundamental concepts to solve these issues:

- **Local Connectivity:** Instead of every neuron connecting to every pixel, filters (kernels) connect only to small local spatial regions (receptive fields, e.g., $3 \times 3$ or $5 \times 5$).
- **Weight Sharing:** The same filter is slid across the entire spatial domain. This allows the model to detect the same feature regardless of its position, drastically reducing parameter count while preserving spatial structure.

### Convolution versus MLP

- **MLP:** Scales poorly with image sizes, uses weights inefficiently by learning localized features separately at every grid coordinate, and destroys spatial geometry upon input flattening.

- **CNN:** Parameter count is independent of input spatial dimensions (depending only on kernel size and channel depth), leading to smaller, parameter-efficient neural networks that inherently preserve spatial topology.

### Convolution Arithmetic

The shape of the output feature map (activation map) depends on:

1. **Shape of the input feature map:** Height $H$ and Width $W$.
2. **Kernel size:** Height $h$ and Width $w$ (or $k \times k$).
3. **The stride ($s$):** Controls how many pixels/grid units the filter moves at each step.
4. **The padding ($p$):** Adding extra rows or columns (typically zeros) around the border to prevent spatial dimension shrinking and process edge pixels.

- **Output Dimensions:**
$$H_{\text{out}} = \left\lfloor \frac{H - h + 2p}{s} \right\rfloor + 1, \quad W_{\text{out}} = \left\lfloor \frac{W - w + 2p}{s} \right\rfloor + 1$$
### How does the filter work on RGB / Multi-Channel inputs?

1. $C_{\text{in}}$ input channels (3 for RGB, or multiple atmospheric variables/pressure levels like $U_{850}, V_{850}, Z_{500}, T_{2m}$).
2. 1 filter contains $C_{\text{in}}$ separate 2D spatial kernels (one per input channel).
3. Each kernel convolves with its respective input channel, and the results across all channels are summed element-wise.
4. A scalar bias term $b$ is added to yield 1 output channel feature map:
$$\mathbf{Y}_{c_{\text{out}}} = \sigma \left( b_{c_{\text{out}}} + \sum_{c_{\text{in}}=1}^{C_{\text{in}}} \mathbf{X}_{c_{\text{in}}} * \mathbf{K}_{c_{\text{out}}, c_{\text{in}}} \right)$$

### Building a Convolutional Neural Network (CNN)

### Feature Extraction

- **Convolutional layer:** Applies sliding learnable filters across input tensors to extract spatial feature maps.
- **Non linearity:** Applies element-wise activation functions (e.g., ReLU, GELU, LeakyReLU) to introduce non-linear mapping capabilities.
- **Pool:** Downsamples spatial dimensions to aggregate local features, reduce computational load, and expand the receptive field of subsequent layers- .

### Task Dependent
- **FC (Fully Connected Layer):** Receives flattened feature vectors to combine high-level spatial representations for global scalar predictions.
- **Non linearity:** Activation function between dense layers.
- **Softmax / Output Layer:** Converts output values into class probability distributions (for classification) or continuous physical values (for regression). In spatial-to-spatial tasks (like weather forecasting), dense layers are replaced by convolutional upsampling layers (e.g., Transpose Convolutions).

### Pooling

Downsamples activation maps from convolutional layers. **Max Pooling** extracts the maximum value within each sliding window to preserve peak high-intensity features (e.g., peak wind speeds, localized extreme precipitation), while **Average Pooling** computes the arithmetic mean to smooth spatial fields and retain overall background context (e.g., mean surface pressure).

### Popular CNN-based architectures

- **AlexNet:** Early pioneer (2012) demonstrating deep CNN performance using stacked convolutions, max pooling, ReLU activations, dropout, and dense output layers.

- **ResNets:** Introduces **Residual/Skip Connections** ($\mathbf{y} = \mathcal{F}(\mathbf{x}) + \mathbf{x}$), allowing input signals to bypass intermediate layers, preventing vanishing gradients and smoothing the loss landscape in deep networks.

- **U-Nets:** An Encoder-Bottleneck-Decoder architecture featuring skip connections between corresponding spatial resolutions of the encoder and decoder. E.g., The encoder downsamples atmospheric fields to capture large-scale synoptic context at the bottleneck, while skip connections pass fine-grained local spatial details directly across to preserve localized meteorological features (e.g., convective storms).

- **Periodic convolutions:** Modifies standard zero-padding by circularly wrapping east and west spatial boundaries ($\mathbf{X}_{\text{padded}}[:, \text{left}] = \mathbf{X}[:, \text{east end}]$). E.g., Eliminates non-physical boundary discontinuities at $0^\circ$ and $360^\circ$ longitudes on global spherical grids to maintain continuous zonal fluid flow.

- **Spatio-Temporal Data - ConvLSTMs:** Replaces matrix multiplications inside standard Long Short-Term Memory (LSTM) recurrent cells with 2D convolutional operations to simultaneously model spatial fluid interactions and continuous temporal evolution:
$$\mathbf{i}_t = \sigma(\mathbf{W}_{xi} * \mathbf{X}_t + \mathbf{W}_{hi} * \mathbf{H}_{t-1} + \mathbf{b}_i)$$
$$\mathbf{f}_t = \sigma(\mathbf{W}_{xf} * \mathbf{X}_t + \mathbf{W}_{hf} * \mathbf{H}_{t-1} + \mathbf{b}_f)$$
$$\mathbf{C}_t = \mathbf{f}_t \circ \mathbf{C}_{t-1} + \mathbf{i}_t \circ \tanh(\mathbf{W}_{xc} * \mathbf{X}_t + \mathbf{W}_{hc} * \mathbf{H}_{t-1} + \mathbf{b}_c)$$
$$\mathbf{o}_t = \sigma(\mathbf{W}_{xo} * \mathbf{X}_t + \mathbf{W}_{ho} * \mathbf{H}_{t-1} + \mathbf{b}_o)$$
$$\mathbf{H}_t = \mathbf{o}_t \circ \tanh(\mathbf{C}_t)$$

### Terminology

- **Inductive Bias:** The set of structural assumptions built into a model's architecture that guide it toward certain solutions (e.g., CNNs assume spatial locality, scale hierarchy, and pattern translation invariance/equivariance).
- **Translation equivalence (Equivariance):** The property that shifting the input spatially produces a correspondingly shifted output feature map ($f(T_\Delta(x)) = T_\Delta(f(x))$), meaning a CNN detects features regardless of where they appear in the image.
- **Input size:** The spatial dimensions (Height $\times$ Width) and number of channels ($C$) of the feature map (e.g., an atmospheric state tensor) fed into a convolution layer.
- **Kernel Size:** The spatial height and width ($h \times w$) of the small filter of trainable weights that slides across the input.
- **Stride:** The step size by which the kernel moves across the input, which controls how much the spatial dimension is downsampled.
- **Padding:** Extra values (typically zeros, border values, or circular wraps) added around the border of the input so that the kernel can be applied at the edges without shrinking the feature map.
- **Channels:** The depth dimension of a feature map, where each channel represents a different input physical variable or a learned abstract feature.
- **Pooling:** A downsampling operation (e.g., max or average) that summarizes local regions of a feature map to reduce resolution and expand the receptive field.
- **Residual/Skip Connections:** Shortcuts that add a layer’s input directly to the output of a layer downstream in the network ($\mathbf{y} = \mathcal{F}(\mathbf{x}) + \mathbf{x}$), preserving direct gradient flow to early layers in deep networks and smoothing the loss landscape.

## Graph Neural Networks

Graph Neural Networks (GNNs) are neural networks designed to operate on graph-structured data, where information is represented as nodes and their relationships (edges). GNNs have been used very successfully in building ML weather forecasting models, beginning with Google’s Graphcast, and being applied in AIFS, as well as other AI models.

### Graph Neural networks for weather modelling

#### Motivation

- **Evolution of Layers:** Dense (FC) Layers $\to$ Convolutional (CNN) Layers $\to$ Graph (GNN) Layers.
- **Limitations of CNNs for Earth Systems:**
    - **Regular Euclidean Grid Assumption:** CNNs require flat, uniform 2D/3D rectangular grids. The Earth is a sphere, and projecting a sphere onto a flat 2D grid introduces extreme polar distortion (e.g., longitude grid lines converge at the poles).
    - **Fixed Local Neighborhood:** Convolutions use fixed-size rectangular sliding windows (e.g., $3 \times 3$), which cannot adapt to variable physical distances across latitudes.
    - **Translation Invariance:** CNNs assume spatial relationships are uniform across the domain, failing to account for non-Euclidean spatial distances on a globe.
- **Requirements of Modern Earth System Models:**
    - **Cubed-Sphere & Reduced Gaussian Grids:** Atmospheric models like ECMWF's IFS use reduced Gaussian grids ($O1280$) where grid points are spaced roughly uniformly over the sphere rather than clustered at the poles.
    - **Unstructured Meshes:** Models like ICON (DWD) use unstructured triangular/icosahedral meshes. GNNs natively operate on these non-uniform spatial discretizations without grid interpolation or polar singularities.

#### What is a Graph?

- **Formal Definition:** A graph $G = (V, E)$ is a data structure consisting of a set of **Nodes** (or Vertices, $V$) connected by a set of **Edges** ($E$).
- **Nodes ($V$):** Discrete spatial points representing physical coordinates (e.g., grid points, weather stations, or multi-mesh nodes).
- **Edges ($E$):** Connections defining directional or bidirectional communication channels between nodes. Edges carry attributes such as spatial distances, relative directional vectors, or connectivity types.

##### Graph Features

Information in a GNN is stored across three distinct feature representations:
1. **Node Features ($\mathbf{h}_v \in \mathbb{R}^{d_v}$):** Physical state variables assigned to each node $v$ (e.g., Temperature, Pressure, Geopotential, Wind vectors at time $t$).
2. **Edge Features ($\mathbf{e}_{uv} \in \mathbb{R}^{d_e}$):** Properties of the connection between node $u$ and node $v$ (e.g., 3D spatial distance $\Vert{}x_u - x_v\Vert{}$, relative distance vectors $\Delta x, \Delta y, \Delta z$, terrain slope).
3. **Graph-Level / Global Features ($\mathbf{u} \in \mathbb{R}^{d_g}$):** Domain-wide variables affecting the entire system (e.g., global mean solar insolation, day of year, total atmospheric mass).

#### Build a GNN

##### Inductive Biases of GNNs

- **Locality:** Node updates depend strictly on their immediate graph neighborhood $\mathcal{N}(v)$, defined by local edge connections rather than a rigid spatial matrix window. E.g., An atmospheric node is updated based only on physically connected neighboring grid points within a specified interaction radius.
- **Permutation Invariance & Equivariance:** Graph nodes have no natural numerical ordering (unlike pixels in an image array).
    - **Permutation Invariance:** Reordering the node sequence in memory yields identical global graph-level predictions: $f(P \cdot \mathbf{X}) = f(\mathbf{X})$.
    - **Permutation Equivariance:** Reordering node inputs permutes the output node features by the exact same order: $f(P \cdot \mathbf{X}) = P \cdot f(\mathbf{X})$.

##### The Message Passing Algorithm

Message passing is the fundamental operation of GNNs. For every node $v$, information is gathered from its connected neighbors $u \in \mathcal{N}(v)$ across three steps:

1. **Message Generation:** Compute a message vector $\mathbf{m}_{v \leftarrow u}$ along edge $(u, v)$ using a shared MLP $\phi_e$:
$$\mathbf{m}_{v \leftarrow u} = \phi_e\left(\mathbf{h}_u^{(l)}, \mathbf{h}_v^{(l)}, \mathbf{e}_{uv}\right)$$
2. **Message Aggregation:** Aggregate incoming messages from all neighbors $\mathcal{N}(v)$ using a symmetric, permutation-invariant aggregation operator $\bigoplus$ (e.g., $\text{Sum}$, $\text{Mean}$, or $\text{Max}$):
$$\mathbf{\bar{m}}_v^{(l)} = \bigoplus_{u \in \mathcal{N}(v)} \mathbf{m}_{v \leftarrow u}$$
3. **Node State Update:** Update node $v$'s state using another shared MLP $\phi_v$:
$$\mathbf{h}_v^{(l+1)} = \phi_v\left(\mathbf{h}_v^{(l)}, \mathbf{\bar{m}}_v^{(l)}\right)$$

#### Scaling & Core Ingredients of GNNs

##### Stacking GNN Layers

- Stacking $L$ message-passing layers expands the **receptive field** of each node to encompass its $L$-hop neighborhood. E.g., A 16-layer GNN allows information to propagate across 16 edge steps, enabling local dynamics to interact over global synoptic distances.

##### The Two Computational Pillars of GNNs

1. **Shared MLPs:** Small Multilayer Perceptrons ($\phi_e, \phi_v$) whose parameters are shared across all nodes and edges in the graph, ensuring parameter efficiency regardless of total graph size.
2. **Sparse Index-Gather / Index-Scatter:** High-performance sparse operations that collect data from connected neighbors (`gather`) and distribute aggregated updates back to target nodes (`scatter`).

#### The Encoder-Processor-Decoder Architecture

Modern weather GNNs (like GraphCast and AIFS) isolate atmospheric prediction into three modular stages:

1. **Encoder (Grid to Graph / Mesh2Graph):** Maps high-resolution physical grid data (e.g., $0.25^\circ$ ERA5 lat-lon or reduced Gaussian grid) onto a latent multi-resolution graph.
2. **Processor (Graph to Graph):** Performs $L$ successive message-passing iterations on the homogeneous multi-mesh graph in latent space to simulate fluid dynamics and energy transfers.
3. **Decoder (Graph to Grid / Graph2Mesh):** Maps updated latent node representations back to the original physical forecast grid to produce predicted atmospheric states $\hat{\mathbf{X}}_{t+\Delta t}$.

### GNN Weather Forecasting Models & Ecosystem

#### Key GNN Models in Numerical Weather Prediction

- **GraphCast (DeepMind):** Uses an **Encoder-Processor-Decoder** pipeline. The processor operates on an **Icosahedral Multi-Mesh** (a sequence of recursively refined icosahedrons superimposed on the sphere) to allow ultra-fast long-range interaction paths across the globe.

- **AIFS (ECMWF Data-Driven Model):** ECMWF's operational AI weather model using message-passing graph architectures built over reduced Gaussian grids.

- **GraphDOP:** GNN model applied to radar rainfall nowcasting and doppler atmospheric data processing.

#### Software Ecosystem

- **PyG (PyTorch Geometric):** Standard open-source deep learning library for graph-structured data built on top of PyTorch.
- **Anemoi Graphs (`anemoi-graphs`):** ECMWF open-source library specifically designed to build, manipulate, and optimize spatial graphs for weather and climate neural network architectures.

### Terminology

- **Graph:** A mathematical structure $G=(V, E)$ consisting of nodes $V$ (points) and edges $E$ (connections) used to represent non-Euclidean spatial relationships.
- **Message Passing:** Iterative algorithm where nodes generate messages from neighboring states, aggregate them via symmetric operations (sum/mean), and update their local features.
- **Processor:** The multi-layer internal GNN engine executing iterative message passing on latent graphs between the encoder and decoder.
- **Permutation Invariance:** Property ensuring that node storage order does not change graph-level predictions.
- **Icosahedral Multi-Mesh:** A multi-scale spherical graph created by subdividing an icosahedron into nested levels, allowing short spatial jumps across global distances.
- **Mesh2Graph / Graph2Mesh:** Bipartite mapping graphs used to transform physical grid data to latent graph representations (and back).

## Transformer Neural Networks

### Introduction

Transformers are neural network architectures based on **attention mechanisms**, which dynamically weight interactions between all elements in a dataset regardless of their spatial or temporal distance. Unlike traditional recurrent or convolutional networks, transformers model long-range dependencies across sequence tokens or spatial fields without relying on sequential step-by-step processing.

Originally developed for natural language processing (NLP)—powering large language models like ChatGPT and Claude—transformers have become foundational in earth system modeling, spatiotemporal forecasting, and data-driven weather prediction systems (e.g., ECMWF's Artificial Intelligence Forecasting System, **AIFS**).

What are transformers made of?
- Seq2seq modelling: Predict next token in a sequence 

### What Are Transformers Made Of?

#### Seq2Seq Modelling

Sequence-to-sequence (Seq2Seq) modeling aims to map an input sequence $\mathbf{X} = (\mathbf{x}_1, \dots, \mathbf{x}_T)$ to an output sequence $\mathbf{Y} = (\mathbf{y}_1, \dots, \mathbf{y}_{T'})$. In traditional autoregressive modeling, the network predicts the next token $\mathbf{x}_{t+1}$ conditioned on all previous tokens $(\mathbf{x}_1, \dots, \mathbf{x}_t)$. In weather and spatial domains, tokens represent local spatial patches or temporal state vectors rather than discrete words.

#### Attention and Sequence Modelling

##### Attention Is All You Need!

Introduced by Vaswani et al. (2017), the core premise of the transformer architecture is that recurrence (RNNs/LSTMs) and convolutions (CNNs) can be entirely replaced by self-attention mechanisms. This removes sequential computational bottlenecks, enabling massive parallelization during training across entire time series or spatial domains.

##### Why LSTM Instead of Attention in Rainfall-Runoff?

While transformers dominate high-dimensional spatial forecasting (e.g., AIFS), Recurrent Neural Networks like **LSTMs** remain highly effective for 1D rainfall-runoff modeling (e.g., CAMELS hydrology benchmarks) due to specific domain properties:

- **Mass Balance & Physical Memory:** Hydrological systems act as dynamical accumulators (soil moisture, groundwater storage). An LSTM's cell state $c_t$ acts as an explicit physical reservoir that naturally conserves mass over continuous time steps ($O(T)$ linear memory).

- **Computational Complexity:** Self-attention scales quadratically $O(T^2)$ with sequence length $T$. For long multi-year continuous hydrological hydrographs ($T > 10,000$ daily/hourly steps), standard attention creates severe memory bottlenecks.

- **Inductive Bias & Data Efficiency:** Catchment response follows sequential causality (rainfall today affects discharge tomorrow). LSTMs bake in this strong temporal inductive bias, allowing them to train effectively on smaller hydrological datasets, whereas transformers lack temporal priors and require massive data to learn time-ordering from scratch.

#### What Is Attention?

At its core, attention is a **dynamic similarity measure** calculated between vectors in a learned latent space $\mathbb{R}^E$:

1. **Similarity Computation:** Compute the scalar agreement (dot product) between two hidden state vectors $\mathbf{h}_i, \mathbf{h}_j \in \mathbb{R}^E$:
$$\text{similarity}(i, j) = \mathbf{h}_i \cdot \mathbf{h}_j^T$$
2. **Normalisation via Softmax:** Convert raw similarity scores into a normalized probability distribution (weights $\alpha_{i,j} \in [0, 1]$ that sum to 1) using the Softmax activation function:
$$\text{Softmax}(\mathbf{x})_i = \frac{e^{x_i}}{\sum_{j} e^{x_j}}$$

	_Softmax acts as a smooth, differentiable version of $\text{argmax}$, ensuring the model can assign high weight to relevant tokens while remaining fully trainable via backpropagation._

3. **State Update:** Update the representation of token $i$ by taking a weighted sum of all surrounding latent states based on their similarity scores $\alpha_{i,j}$.


#### How Can We Make This Learnable?

To make attention adaptive to different physical or semantic relationships, the raw token representations are projected into three distinct spaces using learned weight matrices $W_Q, W_K, W_V \in \mathbb{R}^{E \times d_k}$:

- **Query ($\mathbf{q}_i = \mathbf{x}_i W_Q$):** What token $i$ is looking for.

- **Key ($\mathbf{k}_j = \mathbf{x}_j W_K$):** What token $j$ contains.

- **Value ($\mathbf{v}_j = \mathbf{x}_j W_V$):** The actual information token $j$ passes along.


$$\text{Attention}(Q, K, V) = \text{Softmax}\left(\frac{Q K^T}{\sqrt{d_k}}\right) V$$

_The scaling factor $\sqrt{d_k}$ (where $d_k$ is the feature dimension) prevents the dot product from growing excessively large in high dimensions, which would push the Softmax function into regions with near-zero gradients._


### Transformer Encoder
#### Input

Input data (e.g., a 2D weather field split into spatial patches or a multi-variate climate time series) is tokenized into a 2D matrix of shape $(\text{Num\_Tokens}, \text{Input\_Dim})$.

#### Embedding + Positional Encoding

- **Embedding:** A linear layer maps raw input dimensions into a uniform latent dimension $E$ ($\mathbb{R}^{\text{Num\_Tokens} \times E}$).
- **Positional Encoding:** Because self-attention is **permutation-invariant** (treating input tokens as an unordered set), spatial or temporal geometry must be manually injected. Positional encodings (fixed sinusoidal functions or learned vectors) are added element-wise to the embeddings to preserve sequence order or spatial lat/lon locations.

#### Transformer Block

A standard Transformer Encoder consists of stacked, repeatable blocks containing:

1. **Multi-Head Self-Attention (MHA):** Runs $H$ independent attention mechanisms ("heads") in parallel, allowing the model to simultaneously focus on different physical patterns (e.g., Head 1 tracks local pressure gradients, Head 2 tracks global Rossby wave patterns).

2. **Layer Normalization (LayerNorm):** Stabilizes training dynamics by normalizing features across channels for each token independently.

3. **Multi-Layer Perceptron (MLP):** A 2-layer feed-forward network applied to each token independently to process and transform the mixed attention representations.

4. **Residual Connections:** Skip-connections added around MHA and MLP sub-layers to prevent gradient degradation in deep architectures:
   $$\mathbf{x}^{(l)} = \text{MLP}(\text{LN}(\mathbf{x}')) + \mathbf{x}', \quad \text{where } \mathbf{x}' = \text{MHA}(\text{LN}(\mathbf{x})) + \mathbf{x}$$

#### Encoder vs. Decoder Architecture

- **Original Transformer (Vaswani et al.):** Designed for machine translation using an **Encoder** (processes source language A) and a **Decoder** (generates target language B autoregressively).
- **Encoder-Only Models (e.g., ViT, AIFS):** Most vision and weather transformers use encoder-only setups to process global spatial fields simultaneously into a refined latent state without requiring step-by-step text-style decoding.

### Extensions

- **Sparse Attention:** Reduces the standard quadratic computational complexity $O(N^2)$ to $O(N \sqrt{N})$ or $O(N \log N)$ by restricting attention to local windows, dilated grids, or high-value routing paths (essential for global high-resolution weather grids).

- **Sharded Keys & Values (Grouped-Query Attention - GQA):** Shares Key ($K$) and Value ($V$) heads across multiple Query ($Q$) heads to drastically cut GPU memory footprint during inference.

- **QK LayerNorm:** Applies Layer Normalization directly to Query ($Q$) and Key ($K$) vectors before computing dot products to prevent attention logits from exploding during long-duration or mixed-precision training runs.

### Why use Transofrmers?

### Pros

- **Structural Flexibility:** Completely agnostic to input topology—treats images, graphs, 1D time-series, and unstructured weather grids identically as sets of tokens.
- **Missing Value & Mask Resilience:** Handles missing observational data natively by masking out invalid token indices during attention computation.
- **Massive Parallelization:** Computes interactions across all tokens concurrently, making full use of modern GPU/TPU parallel hardware during training.

### Cons

- **High Computational Cost:** Standard self-attention memory scales quadratically $O(N^2)$ with the number of spatial/temporal tokens $N$.
- **Weak Inductive Bias:** Lacks built-in spatial (CNN) or temporal (RNN) priors; requires massive training datasets to discover basic geometric and physical relationships from scratch.

### Summary

- Transformers process data as sets or sequences of **tokens** using dynamic **self-attention** mechanisms.
- Domain customization happens strictly at the **tokenization** and **embedding** stage; the underlying Transformer blocks remain standardized.
- While computationally efficient to run on specialized hardware, high-resolution global modeling requires **sparse attention** variants to overcome $O(N^2)$ memory scaling.

### Terminology

- **Hidden / Latent Space:** A compressed, learned vector space $\mathbb{R}^E$ where semantically or physically similar data states are mapped close together.
- **Tokens:** Discrete vector units (e.g., word embeddings or $16 \times 16$ spatial image/grid patches) fed into a transformer.
- **Attention:** An adaptive mechanism computing dynamic weights between tokens to determine how much information to pass across the graph/sequence.
- **SoftMax Activation:** A function converting raw scalar logits into normalized probabilities summing to 1.0 ($\text{Softmax}(\mathbf{x})_i = \frac{e^{x_i}}{\sum_j e^{x_j}}$).
- **Transformer Block:** A core repeatable module combining Layer Normalization, Multi-Head Attention, Residual Connections, and a point-wise MLP.
- **Projection Head:** A final Linear/MLP layer attached to an encoder's output to map latent representations back to physical prediction variables (e.g., predicting temperature, pressure, or precipitation at target coordinates).
- **Vision Transformer (ViT):** An architecture that reshapes 2D/3D spatial grids into flat sequences of patches, treating spatial vision/weather tasks as token sequence problems.

## Generative Models


Generative models learn the underlying probability distribution of training data to produce new, plausible samples. While widely known for generating text (LLMs), images, and videos, they have become vital in atmospheric science for **ensemble weather forecasting**—generating a set of physically realistic future states to quantify weather uncertainty.

## What Are Generative Models?

Unlike discriminative models that learn a boundary $p(y\vert{}x)$ to map inputs to labels, generative models estimate the data distribution $p(x)$ (or conditional distribution $p(x\vert{}y)$). By sampling from this learned distribution, they can produce new instances that mirror the statistical structure of real-world observations.

## Generative Modelling of Atmospheric Fields

### Usage of $p(x\vert{}y)$ in Weather Forecasting

In Earth system modeling, we typically care about **conditional generation** $p(x\vert{}y)$, where we condition the generated atmospheric state $x$ on a given context $y$:

- **Forecasting:** $y$ is the current/past atmospheric state ($x_t$), and $x$ is the future state ($x_{t+\Delta t}$). Sampling $p(x\vert{}y)$ generates an ensemble of realistic future weather scenarios.
- **Downscaling:** $y$ is a low-resolution field (e.g., $1^\circ$ global model), and $x$ is a high-resolution regional field (e.g., $0.05^\circ$ local grid with mountain microclimates).
- **Dataset / Domain Translation:** $y$ is raw observational data (e.g., GEO satellite ring radiances), and $x$ is the corresponding physical state in reanalysis format (e.g., ERA5 temperature/moisture fields).

## How to Learn $p_\theta(x)$

### What Is Our Loss Function?

The standard principled approach to fitting a generative model $p_\theta(x)$ is minimizing **Negative Log-Likelihood (NLL)** over the training dataset:

$$\mathcal{L}(\theta) = -\mathbb{E}_{x \sim p_{\text{data}}}\left[\log p_\theta(x)\right]$$

Minimizing NLL forces the parameterized model density $p_\theta(x)$ to allocate high probability mass to real atmospheric observations. However, because high-dimensional atmospheric distributions $p(x)$ are intractable to evaluate directly, different architectures approximate this objective.

### Variational Autoencoders (VAEs)

A VAE approximates $p(x)$ by introducing a low-dimensional continuous latent space $z$:

$$\text{Input } x \;\longrightarrow\; \text{Probabilistic Encoder } q_\phi(z\vert{}x) \;\longrightarrow\; \text{Sampled Latent } z \;\longrightarrow\; \text{Probabilistic Decoder } p_\theta(x\vert{}z) \;\longrightarrow\; \text{Reconstructed } \hat{x}$$

Instead of optimizing NLL directly, VAEs maximize the **Evidence Lower Bound (ELBO)**:

$$\mathcal{L}_{\text{VAE}} = \underbrace{\mathbb{E}_{q_\phi(z\vert{}x)}\left[\log p_\theta(x\vert{}z)\right]}_{\text{Reconstruction Loss}} - \underbrace{D_{\text{KL}}\left(q_\phi(z\vert{}x) \;\vert{}\vert{}\; p(z)\right)}_{\text{KL Divergence Regularization}}$$

- **Reconstruction Loss:** Measures how accurately the decoder reconstructs the atmospheric state.
- **KL Divergence:** Forces the encoder's latent distribution to stay close to a standard normal Gaussian prior $p(z) = \mathcal{N}(0, \mathbf{I})$.

### How to Apply This to Weather Forecasting

1. **Training:** The encoder learns to compress 2D/3D atmospheric states into a smooth Gaussian latent space $z$, while the decoder learns to map latent points back into physical atmospheric fields.
2. **Inference (Ensemble Generation):** Given a current condition $y$, we sample multiple random vectors $z^{(1)}, z^{(2)}, \dots, z^{(K)} \sim \mathcal{N}(0, \mathbf{I})$ and pass them through the conditional decoder $p_\theta(x\vert{}z, y)$. This outputs $K$ distinct, physically consistent weather forecasts representing chaotic flow uncertainty.

## Terminology

- **Conditional Generation $p(x\vert{}y)$:** Modeling the probability distribution of outputs $x$ given a context $y$. In weather forecasting, $y$ represents past observations/initial conditions, and $x$ represents target future states or higher-resolution fields.
- **Autoencoder (AE):** A deterministic neural network that compresses an input field into a low-dimensional bottleneck (latent vector) via an encoder, then reconstructs the original field via a decoder. Standard autoencoders lack a continuous latent space structure and cannot sample new realistic data.
- **Variational Autoencoder (VAE):** A probabilistic autoencoder whose encoder predicts a mean $\mu$ and variance $\sigma^2$ (a Gaussian distribution) in latent space. The KL divergence penalty ensures the latent space is dense and smooth—sampling any random Gaussian vector $z$ yields a realistic physical field.
- **Diffusion Model:** A generative model trained to iteratively reverse a noise process. It learns to inspect a corrupted, noisy atmospheric field $x_t$ and predict the added noise $\epsilon_\theta(x_t, t)$. This is equivalent to estimating the **score function** $\nabla_x \log p(x)$ (the gradient pointing toward higher real-data probability). During inference, the model starts from pure Gaussian noise and applies step-by-step corrections (annealing) to synthesize a crisp, high-resolution atmospheric field.
